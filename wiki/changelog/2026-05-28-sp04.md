# SP-04: File Interface — 2026-05-28

## Summary

Implemented three concrete `FileSource` subclasses and a factory so the
processing pipeline can read stdin, small files, and large files through
a single typed interface.

## New API

| Symbol | Header | Description |
|--------|--------|-------------|
| `cc_cut::mmap_threshold` | `include/cut/file_source.hpp` | 100 MiB dispatch threshold (constexpr) |
| `cc_cut::FileSource::next_line` | `include/cut/file_source.hpp` | Protected static line-splitter shared by all subclasses |
| `cc_cut::StdinSource` | `include/cut/stdin_source.hpp` | Reads all stdin into memory on load() |
| `cc_cut::BufferedFileSource` | `include/cut/buffered_file_source.hpp` | Reads file < mmap_threshold into memory |
| `cc_cut::MmapFileSource` | `include/cut/mmap_file_source.hpp` | Memory-maps file >= mmap_threshold via Boost.Iostreams |
| `cc_cut::make_file_source` | `include/cut/make_file_source.hpp` | Factory: "-" → StdinSource, small → Buffered, large → Mmap |

## Behavior Notes

- Lines delimited by `\n`. `\r` before `\n` is included in the returned `string_view` — no CRLF normalization. Field processors handle `\r` if needed.
- Empty file: `load()` succeeds; `getline()` returns `nullopt` immediately.
- Factory errors: `"cc-cut-tool: <path>: <reason>"` (no trailing newline).
- `make_file_source` does NOT call `load()` — callers must call it.
