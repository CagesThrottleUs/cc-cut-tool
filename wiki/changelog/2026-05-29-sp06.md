# SP-06: Byte Mode — 2026-05-29

## Summary

`-b` mode is now functional end-to-end. `main.cpp` is simplified to a single
`make_processor` call; a new Processor strategy pattern handles all mode dispatch
so main.cpp contains no CutMode comparisons.

## New API

| Symbol | Header | Description |
|--------|--------|-------------|
| `cc_cut::Processor` | `include/cut/processor.hpp` | Abstract base for all mode processors |
| `cc_cut::make_processor(opts)` | `include/cut/processor.hpp` | Factory: dispatches by CutMode, returns `std::expected<unique_ptr<Processor>, string>` |
| `cc_cut::ByteProcessor` | `include/cut/byte_processor.hpp` | Processes byte mode for a given CutOptions |
| `ByteProcessor::select_bytes(line, list)` | same | Raw byte selection by CutList position |
| `ByteProcessor::select_bytes_no_split(line, list)` | same | UTF-8-boundary-aware selection (-n flag) |
| `ByteProcessor::process_line(line, out)` | same | Selects bytes, writes result + newline |
| `ByteProcessor::run(out, files, err)` | same | Iterates files, returns exit code |

## Behavior Notes

- `-b` mode: byte positions are 1-based in CLI, 0-based internally (existing CutList convention)
- `-n` flag with `-b`: includes/excludes whole UTF-8 characters based on lead byte position
- Invalid UTF-8 bytes under `-n`: treated as 1-byte characters (never skipped or crashed on)
- `-c` (character mode): rejected with `cc-cut-tool: character mode not yet implemented` (exit 1)
- `FieldProcessor` now inherits `Processor`; existing field mode behavior unchanged

## Architecture

`make_processor` replaces the `if (mode != FIELD) { error }` guard in main.cpp.
Adding a new mode now requires only updating `make_processor`, not main.cpp.
